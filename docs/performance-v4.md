# V4 渲染性能维护

本次只调整 `scene.ts` 的执行方式。山体网格、粒子数量、着色器光照与纹理、分辨率策略、镜头路径和动画参数均保持原值；未新增静态替代或限帧模式。原有无 WebGL 与系统减少动画偏好仍按原逻辑处理。

## 优化

- 将六个网格的初始化分段执行，避免一次长任务阻塞交互。
- 使用 Three.js `compileAsync` 预热着色器，准备好后启动原来的逐帧动画。
- 缓存文字避让区域：滚动、布局、字体或相关元素的变换发生变化时失效，静止时复用。
- 天空放在不透明山体之后绘制，并使用远平面深度测试。被山体遮挡的天空不再重复执行大气着色器，最终可见像素保持一致。
- 修正尺寸记录与布局观察，防止重复分配绘图缓冲区并保持缓存及时更新。

技术依据：[Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)。本次未新增依赖。

## 2026-10-12 验证

使用独立 Edge、硬件加速的 NVIDIA RTX 5060 Laptop GPU；视口 1440 × 900、DPR 2，沿用原来的 DPR 上限，绘图缓冲区为 3,969,000 像素。原版与最终版均能接近屏幕的 180Hz；修复主要减少首屏初始化阻塞，而非提高这一设备的峰值帧率。

- 最终版连续滚动采样约 180 FPS，P95 帧时 6ms，无超过 34ms 的采样帧。
- 原版首次进入曾采集到 72ms、354ms 的主线程长任务；最终采样未记录到超过 50ms 的长任务。此结果是短时本机采样，不能外推至所有浏览器、设备或网络。
- 固定时间、随机种子和视口的画面对比：首屏逐像素一致；隐私区最大通道差异 2/255，没有任何像素的通道差异超过 5/255。普通播放的镜头与动画参数没有修改。
- 15 项单元测试、27 项已有浏览器测试、1 项新增缓存回归测试通过；类型检查、公开边界检查、生产构建与 Pages 子路径测试通过。
- 新增回归测试验证了静止时减少位置读取、山体仍持续绘制、绘图缓冲区尺寸不下降。

软件渲染对照不代表用户电脑的实际帧率。在缺少 GPU 加速的环境中，不能保证保留同样画质仍达到 60 FPS。后续验收应同时记录实际 WebGL 渲染器、初次进入的长任务、连续滚动帧时和画面对比，不能仅以构建成功或能启动 WebGL 为依据。

## 2026-10-13 手机端流畅度

问题：手机前两屏进入与快速滑动时掉帧；手指一甩后惯性滚动中背景“跳跃”。

- 根因一：文字光晕（5 层模糊 text-shadow，最大 16px）在新章节文字进入时要在 GPU 上光栅化约 150ms，期间 WebGL 画面冻结，随后一下追上，即“跳跃”。触屏/窄屏改为不绘制光晕，依靠粒子场在文字块后的自动避让保证可读性；页眉、声音按钮、预览标签同样去掉毛玻璃。
- 根因二：地址栏在甩动时收起/弹出会改变 innerHeight。手机端画布固定为 100lvh，场景按画布尺寸取景，不再随地址栏重新取景。
- 低端机余量：手机粒子 46k → 32k（点略放大以保持星环饱满），像素比 1.75 → 1.3；≥105Hz 屏幕上粒子场固定 60fps；若中位帧间隔仍明显超出刷新周期，在页面静止时把渲染分辨率降一级（最多两级：1.1、0.9），点数与形态不变。
- 启动：形状缓冲逐个上传、取景计算独立成任务并减少采样，场景出现后的 ScrollTrigger 重算放到空闲时。
- 验证（390×844 触屏模拟，CPU 4× 降速，生产构建）：首次甩动的最长帧由 133ms 降到 16.8ms，三次甩动零掉帧（机器空闲时段，同时段交替对比）。真机 GPU 表现需在手机上复核。

## 2026-10-14 取消手机限帧

问题：手机上滑动约一秒后粒子开始变卡。根因是上一轮加入的“≥105Hz 屏幕粒子场固定 60fps”：刷新率要采样 120 帧才确定，确定后粒子立即降为半帧率，而页面本身仍以 120Hz 滚动，两者不同步即表现为卡顿。

- 底线：任何情况下不降帧率。删除 120Hz 限帧与静止时隔帧绘制，每次屏幕刷新都绘制。
- 默认原画质：删除快速甩动时缩小虚化粒子（22 → 12px）的处理。
- 仅当实测 GPU 跟不上（约 90 帧的中位帧间隔 > 1.2× 刷新周期）时，在页面静止后降一级渲染分辨率（1.3 → 1.1 → 0.9 → 0.75），点数、形态、帧率不变。
- 真机 120Hz 表现需在手机上复核。
